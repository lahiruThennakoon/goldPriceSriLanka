- (decision) AD-1 [ADOPTED from PRD addendum]: Next.js App Router + TypeScript as the paradigm -- server route handlers own all external I/O, client components own presentation/local state only. Binds: all. Prevents: client code calling third-party APIs directly (key leakage, divergent fetch logic).
- (decision) AD-2: Define a MarketDataProvider adapter interface (getSpotGoldUsd, getUsdLkrRate) behind the API route -- concrete vendor is swappable. Binds: market-data fetch (FR1). Prevents: vendor lock-in leaking into client code or being hardcoded in multiple places.
- (decision) AD-3 [ADOPTED from PRD out-of-scope]: No backend database or account system -- all user state (settings, holdings, alerts, recorded price snapshots) lives in browser storage only, namespaced under one localStorage root key. Binds: My Gold (FR8-11), Settings (FR19), Price History (FR12-13). Prevents: two features independently inventing incompatible storage schemas or a partial backend creeping in.
- (decision) AD-4: Price-history snapshots are captured client-side on app foreground (at most once per configured refresh interval), appended to a capped local ring buffer, never backfilled or fetched from a server history endpoint in v1. Binds: FR12-13. Prevents: a future implementer wiring a server-side history table that contradicts the no-backend rule (AD-3).
- (decision) AD-5: The API route always returns a discriminated payload with an explicit freshness/availability flag (fresh | stale-cache | unavailable) -- it never fabricates a plausible-looking number when both live fetch and server cache are empty. Binds: FR1, NFR2. Prevents: a client or route implementation silently guessing/defaulting a price instead of surfacing unavailability.
- (decision) AD-6: The Notification/Push subscription is created only at the moment the user completes the first alert or digest setup action, never eagerly at service-worker install or app launch. Binds: FR14, FR16. Prevents: a service-worker implementation that auto-subscribes on install, contradicting the permission-at-point-of-value UX rule.
- (version) Next.js: use the current 'latest' tag via create-next-app at implementation time (App Router, TypeScript, Tailwind template) rather than pinning a training-data-remembered version number -- npm resolves true-current at install time, which is the verification.
